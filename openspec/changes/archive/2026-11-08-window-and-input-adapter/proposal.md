# Proposal

## Why

Huynity имеет полностью рабочий контур программного рендеринга (`SoftwareRenderer`), модель сцены (`Core`) и главный цикл (`Runtime`), однако вывод изображения ограничен программными тестами в headless-буфер `ImageBuffer`. Для запуска реальной игры или интерактивного приложения движку необходим оконный адаптер, который открывает системное окно, отображает готовый кадровый буфер и поставляет события ввода от пользователя (клавиатура, мышь, окно).

## What Changes

- Реализовать платформенный оконный компонент в `adapters/window/` с чистой изоляцией: зависимость только от `engine/image` и платформенных API окна.
- Реализовать контракт `runtime::PresentationPort` для синхронного или асинхронного показа готового `ImageBuffer` на экран окна без лишних копий пикселей.
- Поддержать корректную обработку изменения размера окна (`WindowResized`) с интеграцией в монотонные поколения поверхности `SurfaceState` конвейера `FramePipeline`.
- Реализовать подсистему событий ввода (`InputEvents`): события клавиатуры (нажатие, отпускание, скан-коды), события мыши (движение, абсолютные/дельта-координаты, нажатие кнопок, колесо прокрутки) и закрытие окна.
- Предоставить снимки синхронного состояния ввода (`InputState`) для прямого чтения игровыми системами в фазе `onUpdate(dt)`.
- Предоставить детерминированный `HeadlessWindow` / `MockWindow` для автоматического тестирования в CI без графического сервера.
- Интегрировать адаптер в корневой CMakeLists под опцией `HUYNITY_BUILD_ADAPTERS` с возможностью сборки через платформенный backend или SDL3/SDL2 при наличии в системе.

## Capabilities

### New Capabilities

- `window-presentation`: создание и жизненный цикл системного окна, реализация `PresentationPort`, показ `ImageBuffer`, обработка изменения размеров поверхности и синхронизация поколений.
- `input-dispatch`: сбор, нормализация и диспетчеризация событий клавиатуры, мыши и окна, формирование синхронного `InputState` для игрового цикла.

### Modified Capabilities

Изменений существующих спецификаций (`geometry-runtime-operations`, `scene-management`, `render-extraction`, `frame-scheduling`) не требуется.

## Impact

- Новый компонент: `adapters/window/` (`include/huynity/adapters/window/`, `src/`, `tests/`).
- Новая CMake-цель: `huynity_window` / `huynity::window`, собираемая при включённой опции `HUYNITY_BUILD_ADAPTERS`.
- `engine/runtime` получает готовую реализацию `PresentationPort`.
- Возможность запуска реальных интерактивных демо и игр с окном и управлением с клавиатуры и мыши.
