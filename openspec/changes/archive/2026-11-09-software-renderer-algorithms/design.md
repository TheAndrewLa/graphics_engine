# Design

## Context

В движке Huynity компонент `engine/renderer` реализует синхронный программный рендерер `SoftwareRenderer`. На данный момент в нём работают растеризация треугольников через edge functions с Z-буфером, плоское затенение (flat shading с ambient + directional светом) и попиксельный alpha blending. Для создания полноценных 2D и 3D игр требуются расширенные рукописные алгоритмы формирования изображения без использования сторонних графических API.

## Goals / Non-Goals

**Goals:**
- Реализовать рукописный целочисленный алгоритм Брезенхэма для отрисовки отрезков в 2D и 3D с тестом глубины Z-буфера.
- Добавить режим каркасного рендеринга (wireframe) для визуализации структуры сеток и отладочных контуров.
- Реализовать затенение Гуро (Gouraud shading) через барицентрическую интерполяцию цветов и освещённости вершин треугольника.
- Реализовать текстурированную растеризацию с выборкой пикселей из `ImageBuffer` по UV-координатам (Nearest Neighbor и Bilinear) для 2D-спрайтов и 3D-граней.

**Non-Goals:**
- Mip-mapping и анизотропная фильтрация (на данном этапе достаточно базовой выборки и билинейной интерполяции).
- Попиксельное затенение по Фонгу (Phong shading с интерполяцией нормалей для каждого пикселя) — отложено до отдельной оптимизации.

## Decisions

### 1. Целочисленный алгоритм Брезенхэма для линий

Отрезок между точками $(x_0, y_0)$ и $(x_1, y_1)$ растеризуется с шагом по доминирующей оси с целочисленным накоплением ошибки:

```cpp
void rasterizeLine2D(int x0, int y0, int x1, int y1, Color color, ImageBuffer& fb);
void rasterizeLine3D(int x0, int y0, double z0, int x1, int y1, double z1,
                     Color color, ImageBuffer& fb, std::vector<double>& depth);
```

*Rationale:* Алгоритм Брезенхэма использует только целочисленную арифметику сложения и сдвигов для координат, обеспечивая максимальную скорость софтверной отрисовки без делений в цикле. Для 3D глубина $z$ линейно интерполируется вдоль шагов отрезка.

### 2. Затенение Гуро (Gouraud Shading)

В отличие от Flat Shading, где нормаль рассчитывается один раз на грань:
1. Для каждой из трёх вершин треугольника вычисляется освещённость $C_0, C_1, C_2$ на основе нормали вершины.
2. В цикле растеризации цвет каждого пикселя вычисляется через барицентрические веса, которые уже рассчитываются в `edgeFunction`:
   $$C = w_0 C_0 + w_1 C_1 + w_2 C_2$$

*Rationale:* Барицентрические координаты $w_0, w_1, w_2$ уже вычислены для проверки принадлежности пикселя треугольнику и интерполяции $z$. Повторное их использование для интерполяции цвета не требует дополнительных вычислений геометрии.

### 3. Софтверная выборка текстуры (Texture Sampling)

Выборка из `ImageBuffer` по координатам $(u, v) \in [0, 1]$:
- **Nearest Neighbor:** $x = \text{clamp}(\lfloor u \cdot W \rfloor, 0, W - 1)$, $y = \text{clamp}(\lfloor v \cdot H \rfloor, 0, H - 1)$.
- **Bilinear:** вычисление 4 соседних тексилей и билинейная интерполяция между ними:
  $$\text{lerp}(\text{lerp}(c_{00}, c_{10}, s), \text{lerp}(c_{01}, c_{11}, s), t)$$

*Rationale:* Позволяет выводить 2D-спрайты с прозрачностью (PNG/битмапы) и текстурированные 3D-модели.

## Risks / Trade-offs

- **[Билинейная интерполяция медленнее Nearest Neighbor]** → Выбор режима фильтрации передаётся через параметры материала (`TextureFilter::Nearest` по умолчанию для ретро-стиля и высокой скорости).
- **[Перспективно-корректное текстурирование в 3D требует деления на W]** → Для 3D UV-координаты интерполируются в виде $u/z, v/z$ и делятся на $1/z$, исключая перспективные искажения текстур.
