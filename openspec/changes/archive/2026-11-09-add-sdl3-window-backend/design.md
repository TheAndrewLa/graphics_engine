# Design

## Context

`WindowAdapter` уже задаёт нужный контракт показа и ввода, а `Engine` работает только через фабрику и не зависит от конкретного окна. Сейчас `window_factory.cpp` безусловно возвращает `HeadlessWindow`; нативной реализации нет. Требования зафиксированы в delta-спецификациях `window-presentation` и `input-dispatch`.

Все операции `Engine`, опрос событий и показ кадров выполняются в главном потоке. `ImageBuffer` содержит RGBA8 с явным `stride`, а размеры оконной поверхности в контрактах выражены в физических пикселях.

## Goals / Non-Goals

**Goals:**

- Изолировать SDL3 внутри `huynity_window`, не меняя публичные заголовки и игровой цикл.
- Поддержать корректный показ кадров, ввод, resize, HiDPI и завершение в реальном окне.
- Сохранить детерминированные тесты и сборку на машинах без SDL3 и графического сервера.

**Non-Goals:**

- Одновременная поддержка SDL2, Vulkan, OpenGL или собственного GPU-рендера.
- Изменение `WindowAdapter`, `WindowConfig`, `Engine`, `InputEvent` и формата `ImageBuffer`.
- Асинхронный показ, несколько окон одного приложения как отдельный пользовательский сценарий, меню и текстовый ввод.
- Обязательная установка SDL3 для всех конфигураций проекта.

## Decisions

### 1. Внутренний NativeWindow вместо расширения публичного API

Добавить `src/native_window.h` и `src/native_window.cpp` с final-наследником `WindowAdapter`. Фабрика остаётся единственной точкой создания; consumers получают `std::unique_ptr<WindowAdapter>` как раньше.

SDL-типы объявляются как непрозрачные указатели, а операции с ними выполняются в `.cpp`. Отдельный PIMPL не нужен: внутренний заголовок не входит в публичную include-директорию, поэтому более простой класс с out-of-line деструктором уже скрывает зависимость.

Класс запрещает копирование и перемещение. Он владеет `SDL_Window`, `SDL_Renderer`, `SDL_Texture` и состоянием инициализации видеоподсистемы. Конструктор при неуспехе освобождает уже созданные ресурсы и выбрасывает `std::runtime_error`; `close()` и деструктор идемпотентно освобождают оставшиеся ресурсы.

### 2. Явная политика выбора и fallback

`createWindow` использует `NativeWindow`, если SDL3 найден при конфигурации и `forceHeadless == false`. При `forceHeadless == true` нативная инициализация не выполняется.

Фабрика перехватывает ошибку создания нативного окна, выводит причину в `std::cerr` и возвращает `HeadlessWindow`. Это сохраняет работу CTest и приложений без дисплея, но не скрывает причину от пользователя. `hasNativeWindowSupport()` по-прежнему сообщает только о наличии бэкенда в сборке, а не об успешной инициализации дисплея.

Альтернатива — вернуть `nullptr` или добавить `std::expected` в фабрику — отклонена: она меняет существующие consumers и не даёт автоматической работы headless CI.

### 3. Синхронный показ через streaming-текстуру

Для каждого размера поверхности создаётся streaming `SDL_Texture` формата `SDL_PIXELFORMAT_RGBA32`. `present()`:

1. Проверяет открытость, непустой буфер, формат и совпадение размеров.
2. Пересоздаёт текстуру после изменения физических размеров.
3. Копирует строки через `SDL_UpdateTexture` с учётом `stride`.
4. Выполняет очистку, `SDL_RenderTexture` и `SDL_RenderPresent`.
5. Всегда синхронно возвращает исходный `unique_ptr` для повторного использования пулом.

Ошибки SDL логируются и не приводят к потере буфера. Промежуточная CPU-копия всего кадра не требуется. Альтернатива `SDL_Surface` отклонена: текстура естественнее переиспользуется и не требует пересоздания surface каждый кадр.

### 4. Физические пиксели и HiDPI

Размер буфера определяется через `SDL_GetWindowSizeInPixels`; для отслеживания используется событие изменения pixel size, а не только логического window size. Это исключает несовпадение framebuffer и drawable на HiDPI.

Координаты и дельты мыши пересчитываются из логических координат SDL в физические пиксели по отношению drawable size к window size. При изменении размеров обновляются `WindowSize` и выдаётся один `WindowResizedEvent`.

### 5. Чистое преобразование событий

Преобразование `SDL_Event -> std::optional<InputEvent>` выделяется во внутренний helper без создания окна. Это позволяет тестировать отображение кодов без видеосервера; `NativeWindow::pollEvents` только фильтрует события своего окна, обновляет размер/состояние и добавляет результаты в выходной вектор.

Клавиши отображаются через `SDL_Scancode`, чтобы `W/A/S/D` соответствовали физическим позициям независимо от раскладки. Поддерживаются все существующие буквы, цифры, F1–F12, навигация и модификаторы; `repeat` переносится в `KeyPressedEvent`. Неизвестные клавиши дают `KeyCode::Unknown`, а неизвестные типы событий игнорируются.

Порядок `SDL_PollEvent` сохраняется. События close преобразуются в `WindowCloseRequestedEvent`; фактическое закрытие выполняет текущий `Engine` через `stop()`.

### 6. Минимальный target-scoped CMake-контракт

`find_package(SDL3 QUIET)` остаётся опциональным. Только при найденном `SDL3::SDL3`:

- `native_window.cpp` и helper событий добавляются через `target_sources(huynity_window PRIVATE ...)`;
- `SDL3::SDL3` подключается через `target_link_libraries(huynity_window PRIVATE ...)`;
- `HUYNITY_HAS_NATIVE_WINDOW` остаётся `PUBLIC`, поскольку текущие factory tests используют его как признак конфигурации;
- SDL-заголовки не попадают в публичный API.

Поиск SDL2 удаляется как неиспользуемый: нативной SDL2-реализации не было. Новые SDL-тесты регистрируются только при наличии SDL3 и запускаются с dummy video driver. Существующие тесты продолжают использовать принудительный headless там, где нужна детерминированность.

### 7. Два уровня проверки

Автоматические проверки покрывают mapping событий, выбор headless, жизненный цикл, показ/отклонение кадра и возврат владения. SDL-тесты используют dummy video driver и не требуют видимого дисплея.

Ручная проверка обязательно запускает `huynity_hello_cube --continuous` и `huynity_game_scene --continuous` в реальной графической сессии: проверяются видимое окно, кадр, клавиши, resize и закрытие. Dummy driver не считается доказательством визуального вывода.

## Risks / Trade-offs

- [Fallback при ошибке дисплея снова оставляет приложение без окна] → выводить явную причину и документировать проверку типа созданного адаптера.
- [Dummy driver не подтверждает показ пользователю] → обязательная ручная проверка в Wayland/X11 с реальным кадром.
- [Логические координаты и drawable pixels различаются на HiDPI] → использовать pixel-size API и масштабировать координаты мыши.
- [SDL хранит процессное состояние видеоподсистемы] → сбалансированные init/quit на каждый экземпляр и вызовы только из главного потока.
- [SDL3 отсутствует на части машин] → опциональная конфигурация и отдельная проверка сборки без `find_package(SDL3)`.
- [Ошибка обновления или показа текстуры не имеет канала в существующем API] → логировать её, сохранить владение буфером и не менять `PresentationPort` в этом изменении.

## Migration Plan

1. Сохранить текущую сборку без SDL3 как базовую и добавить опциональное обнаружение SDL3.
2. Включить нативную реализацию только в конфигурации с SDL3; подключить выбор в фабрике.
3. Запустить существующие и новые автоматические тесты, затем ручные оконные сценарии.
4. Обновить документацию и инструкцию установки `SDL3-devel` для Fedora.

Для отката достаточно убрать нативную ветку фабрики и SDL-источники из target: публичных сигнатур и миграции consumers нет.
