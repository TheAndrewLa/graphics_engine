# render-extraction Specification

## Purpose
Определяет преобразование игровой сцены Core в самостоятельные данные кадра без повторной тяжёлой подготовки и задаёт состав 3D, самостоятельного 2D и HUD-изображения.

## Requirements

### Requirement: Независимый снимок кадра
Render Preparation SHALL создавать неизменяемый снимок, который не содержит изменяемых ссылок на Core и сохраняет все необходимые ресурсы на время обработки кадра.

#### Scenario: Сцена изменилась после отправки
- **WHEN** после подготовки снимка Core изменяет преобразование или геометрию объекта
- **THEN** уже подготовленный снимок сохраняет прежнее согласованное состояние, а следующий снимок отражает изменение

#### Scenario: Объект удалён после отправки
- **WHEN** после подготовки снимка объект и его ресурсы удаляются из сцены
- **THEN** данные отправленного снимка остаются доступными до завершения обработки кадра

### Requirement: Полное отображаемое состояние
Каждый снимок SHALL описывать полное отображаемое состояние выбранных сцен, чтобы Renderer не зависел от постоянной реплики сцены или предыдущих сообщений.

#### Scenario: Несколько команд до одного кадра
- **WHEN** перед подготовкой кадра созданы или изменены несколько объектов
- **THEN** один снимок содержит все отображаемые объекты с их итоговым состоянием, а не только последнее изменение

#### Scenario: Снимок обработан независимо
- **WHEN** Renderer получает действительный снимок после обработки другого кадра или без неё
- **THEN** для обработки снимка не требуется история предыдущих дельт

### Requirement: Совместное использование тяжёлых ресурсов
Снимки и экземпляры SHALL совместно использовать неизменяемые массивы геометрии и тесселяции вместо их копирования при подготовке каждого кадра.

#### Scenario: Неизменная геометрия в следующем кадре
- **WHEN** два последовательных снимка используют одну версию mesh
- **THEN** оба снимка удерживают один неизменяемый массив данных mesh без создания независимой копии вершин и индексов

#### Scenario: Экземпляры с разными преобразованиями
- **WHEN** снимок содержит несколько экземпляров одной tessellation
- **THEN** снимок содержит отдельные данные экземпляров и общий render-ресурс, а не mesh на каждый экземпляр

### Requirement: Кеширование по версии геометрии и качеству
Render Preparation SHALL повторно использовать результат тесселяции для неизменной геометрии и эквивалентных параметров качества и SHALL инвалидировать его при изменении этих входов.

#### Scenario: Изменилось только преобразование
- **WHEN** между кадрами изменился transform экземпляра, но не геометрия или параметры тесселяции
- **THEN** используется существующая tessellation без повторного вызова геометрической операции

#### Scenario: Изменилась геометрия или качество
- **WHEN** изменилась версия геометрии или параметры, влияющие на результат тесселяции
- **THEN** новый снимок использует результат для новых входов и не подменяет его устаревшим кешем

#### Scenario: Завершилась устаревшая фоновая подготовка
- **WHEN** результат фоновой тесселяции получен после замены исходной геометрии или параметров качества
- **THEN** результат не попадает в актуальный кеш или снимок для новой версии

### Requirement: Точечное обновление мировых данных
Core SHALL обновлять мировые преобразования и bounds только для данных, зависящих от произошедших изменений, сохраняя корректность статических и незатронутых ветвей.

#### Scenario: Изменился динамический лист
- **WHEN** изменяется локальный transform объекта без потомков
- **THEN** его мировые данные обновляются без повторной тесселяции и без изменения производных данных несвязанных объектов

#### Scenario: Изменился родитель
- **WHEN** изменяется transform родителя
- **THEN** мировые преобразования и bounds зависимых потомков обновляются до построения снимка

### Requirement: Явные 3D, 2D world и HUD-очереди
Снимок SHALL разделять 3D-мир, самостоятельный 2D-мир и экранный HUD в явные очереди с определённым порядком композиции.

#### Scenario: Смешанный игровой кадр
- **WHEN** активная игра содержит 3D-объекты, объекты самостоятельного 2D-мира и HUD
- **THEN** снимок содержит каждую группу в соответствующей очереди и задаёт порядок их композиции

#### Scenario: Независимый 2D-мир
- **WHEN** отображается 2D-мир с собственной камерой
- **THEN** его объекты используют мировые 2D-преобразования и эту камеру, а не экранные координаты HUD

#### Scenario: Экранный HUD
- **WHEN** отображается HUD
- **THEN** его элементы используют экранные координаты, явный слой и порядок независимо от 3D-камеры

### Requirement: Данные визуального представления
Снимок SHALL переносить камеры, параметры очистки, размеры изображения и необходимые визуальные данные экземпляров, включая материалы, освещение 3D-сцены и параметры 2D-прозрачности и слоёв.

#### Scenario: 3D-экземпляр с материалом
- **WHEN** подготавливается видимый 3D-объект
- **THEN** его render-данные связывают локальный render-ресурс, мировое преобразование и неизменяемый материал

#### Scenario: Освещение 3D-сцены
- **WHEN** 3D-сцена использует освещение
- **THEN** снимок содержит согласованный набор параметров света для этого кадра без чтения изменяемой сцены Renderer-ом

#### Scenario: Прозрачный элемент HUD
- **WHEN** подготавливается прозрачный элемент HUD
- **THEN** его render-данные содержат сведения, необходимые для alpha-композиции и явного порядка слоя

### Requirement: Видимость до построения render-очередей
Render Preparation SHALL исключать невидимые и находящиеся вне области камеры объекты из render-очередей, используя согласованные мировые bounds и правила соответствующей камеры.

#### Scenario: Объект вне камеры
- **WHEN** мировые bounds объекта не пересекают область видимости активной камеры
- **THEN** объект не добавляется в render-очередь этого кадра

#### Scenario: Скрытый HUD-элемент
- **WHEN** элемент HUD помечен невидимым
- **THEN** он не добавляется в HUD-очередь, независимо от видимости игрового мира

### Requirement: Конечное представление бесконечной геометрии
Line, Ray и Plane SHALL попадать в снимок только через явно заданное конечное визуализируемое представление; иначе подготовка SHALL вернуть понятную ошибку без частичного снимка.

#### Scenario: Бесконечная геометрия без области визуализации
- **WHEN** отображаемый объект содержит Line, Ray или Plane без конечного представления
- **THEN** подготовка кадра отклоняется с ошибкой соответствующего объекта, а Renderer не получает частичный снимок

#### Scenario: Задано конечное представление
- **WHEN** для такой геометрии заданы допустимые конечные примитивы или область визуализации
- **THEN** в снимок попадают только полученные конечные render-примитивы

### Requirement: Атомарность ошибок подготовки
При ошибке геометрической операции, преобразования или выделения обязательных данных Render Preparation SHALL не отправлять частичный снимок и SHALL оставлять сцену Core согласованной.

#### Scenario: Ошибка тесселяции
- **WHEN** тесселяция обязательного отображаемого ресурса возвращает ошибку или превышает заданный бюджет
- **THEN** подготовка кадра завершается ошибкой без частичного результата, а исходная геометрия и сцена остаются действительными

### Requirement: Владение при использовании views
Любой span или другой невладеющий view в обработке кадра SHALL быть связан с владельцем данных, время жизни которого покрывает всю обработку снимка Renderer-ом.

#### Scenario: Renderer читает mesh через view
- **WHEN** Renderer получает view на позиции или индексы снимка
- **THEN** соответствующий владелец удерживается заданием кадра до прекращения использования view
